# Roadmap (about 45 days, 5 to 6 days a week)

Each day: build something small, commit it, write 3 lines in `daily-log/day-XX.md`.

## Week 1: HTML and planning
- [ ] Day 1: Create repo, folder structure, first commit. Write what the portfolio must say.
- [ ] Day 2: Sketch the layout on paper (mobile first). List sections and pick colours and fonts.
- [ ] Day 3: Page skeleton with semantic tags (header, nav, main, section, footer).
- [ ] Day 4: Add real content: hero text, about, project list, contact.
- [ ] Day 5: Links, images with alt text, a basic contact form.
- [ ] Day 6: Validate HTML, fix issues, review the week.

## Week 2: CSS layout
- [ ] Day 7: Link CSS, reset, box model, CSS variables for colours.
- [ ] Day 8: Typography: font pairing, scale, line height.
- [ ] Day 9: Style the header and navigation with Flexbox.
- [ ] Day 10: Hero section layout.
- [ ] Day 11: Projects section with CSS Grid.
- [ ] Day 12: About and contact sections, spacing system.

## Week 3: Responsive design and components
- [ ] Day 13: Media queries: tablet breakpoint.
- [ ] Day 14: Desktop breakpoint, fluid type with clamp().
- [ ] Day 15: Mobile menu layout (CSS only).
- [ ] Day 16: Reusable button and card styles.
- [ ] Day 17: Hover and focus states, CSS transitions.
- [ ] Day 18: Test on real phone and fix layout bugs.

## Week 4: JavaScript and the DOM
- [ ] Day 19: Select elements, listen to events. Footer year with JS.
- [ ] Day 20: Mobile menu toggle with aria-expanded.
- [ ] Day 21: Dark and light theme toggle.
- [ ] Day 22: Save theme choice in localStorage.
- [ ] Day 23: Smooth scrolling and active nav link.
- [ ] Day 24: Contact form validation with helpful error messages.

## Week 5: Animation
- [ ] Day 25: CSS keyframes: one page-load animation.
- [ ] Day 26: Scroll reveal with IntersectionObserver.
- [ ] Day 27: Hero interaction that reacts to the cursor.
- [ ] Day 28: Animated project cards or expanding rows.
- [ ] Day 29: Respect prefers-reduced-motion.
- [ ] Day 30: Review: remove any animation that does not help.

## Week 6: Real projects and data
- [ ] Day 31: Store projects in a JS array and render them.
- [ ] Day 32: Add filter buttons (All, JavaScript, CSS).
- [ ] Day 33: Fetch data from a public API and show a loading state.
- [ ] Day 34: Handle errors and empty states.
- [ ] Day 35: Add your real mini projects with links to their repos.
- [ ] Day 36: Write short project descriptions.

## Week 7: Accessibility and performance
- [ ] Day 37: Keyboard-only test and visible focus.
- [ ] Day 38: Colour contrast and screen reader check.
- [ ] Day 39: Compress and resize images, lazy loading.
- [ ] Day 40: Lighthouse audit and fixes.
- [ ] Day 41: SEO basics: title, meta description, Open Graph image.
- [ ] Day 42: Cross-browser check (Chrome, Firefox, Safari).

## Week 8: Deploy and polish
- [ ] Day 43: Deploy with GitHub Pages.
- [ ] Day 44: Write the portfolio's own README with screenshots.
- [ ] Day 45: Final polish, clean the code, tidy commit history.
- [ ] Day 46: Share the link on LinkedIn and your GitHub profile.

## Commit message style
`day 12: style contact section` or `feat: add theme toggle`
